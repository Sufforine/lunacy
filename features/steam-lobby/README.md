# Steam lobby

`api/steam_lobby.gd` — автозагрузка, публичный API и стабильная точка RPC
`/root/SteamLobby`. Сцены, UI и компоненты игрока продолжают обращаться к ней.

## Ответственность сервисов

| Файл | Ответственность и состояние |
| --- | --- |
| `services/connection_service.gd` | Инициализация Steam, callbacks, создание и вход в лобби, транспорт, тайм-аут соединения, список игроков и отключение |
| `services/transition_service.gd` | Переход prepare/load, фоновая загрузка сцены, экран загрузки, барьер готовности, спавн хаба/миссии и ожидания отключившихся игроков |
| `services/inventory_service.gd` | Проверка последовательности операций и ревизий, перемещение и использование предметов, обмен с сундуками, снимки инвентаря |
| `services/drops_service.gd` | Выброс, подбор и удаление предметов мира, подтверждение подбора хостом |
| `services/progression_service.gd` | Проверка траты очков атрибутов и рассылка прогресса |
| `services/chat_service.gd` | Имена игроков и выполнение `/give`, `/xp`, `/exp` |
| `services/lobby_service.gd` | Общий доступ к фасаду и единственным экземплярам NetSession, NetSpawner, NetDrops |

Сервисы создаются один раз дочерними узлами автозагрузки. Они используют тот же
MultiplayerAPI и переживают смену игровой сцены. Изменяемое состояние соединения
принадлежит Connection, состояние перехода — Transitions. Фасад предоставляет
совместимые свойства `peer`, `lobby_id`, `is_host`, `is_joining`.

## Правила расширения

- Новая игровая логика размещается в соответствующем сервисе.
- Публичные вызовы сцен и сигналы остаются на SteamLobby.
- Аннотации `@rpc` остаются только на фасаде. Сервис отправляет пакеты через
  `_lobby._rpc_…`, а обработчик фасада сразу передаёт выполнение сервису.
- Между приёмом RPC и чтением `get_remote_sender_id()` нельзя добавлять
  `await` или отложенный вызов: отправитель проверяется синхронно.
- Вызовы между сервисами проходят через узкие методы фасада; скрипты сервисов
  не загружают друг друга, чтобы не создавать циклические зависимости.
- При отключении Connection сбрасывает ожидания перехода и загрузки, удаляет
  сетевые предметы, закрывает транспорт и очищает NetSession. Сами сервисы
  сохраняются для следующего подключения.

## Проверка после изменений

Проверить загрузку скриптов и запуск меню, затем двумя пирами:
передачу профиля и список игроков, загрузку хаба и миссии, готовность спавна,
инвентарь/сундук/лут, прогресс и отключение во время загрузки.
Локальный ENet проверяет маршрутизацию RPC; Steam P2P требует отдельного прогона
на двух Steam-клиентах.
